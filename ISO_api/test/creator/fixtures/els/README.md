# Synthetic Access Fixtures

These files contain fabricated test data only, not a customer database. They are
generated by `deploy/creator/access-reader/src/test/java/re/digitalthread/els/GenerateFixtures.java`.

| File | Format | Purpose |
| --- | --- | --- |
| synthetic.mdb | Access V2000 | Korean text, NFD text, NULL/empty/zero/false, exact decimal, PKs, multiple PART/REV/OP/programs |
| synthetic.accdb | Access V2010 | Same logical records in ACCDB format |
| linked.accdb | Access V2010 | Unavailable external table must be diagnosed without opening its path |
| unsupported.accdb | Access V2007 | Valid but not enabled by the initial verified-format allowlist |

The unavailable paths are test strings only. No external file is needed. An empty
Tool_Milling table is intentional. These fixtures prove reading and indexing,
not complete ELS-to-DT mapping, customer schema compatibility, or machining safety.

## Regeneration

Build the reader project with Maven and Java 17 or later:

```sh
mvn -f deploy/creator/access-reader/pom.xml package
java -cp deploy/creator/access-reader/target/test-classes:deploy/creator/access-reader/target/els-access-reader.jar re.digitalthread.els.GenerateFixtures /tmp/new-els-fixtures
```

Run from `ISO_api`. The destination must not contain any of the generated names;
the generator refuses to overwrite them. Compare semantic test results before
replacing fixtures. Access creation timestamps can change binary checksums, so
byte-identical regeneration is not promised. `checksums.json` identifies the
checked-in copies and must be updated intentionally when replacing them.

The isolated Docker test build also regenerates all four files and tests the
generated copies by default. Mount this directory at `/fixtures` read-only to
test these checked-in copies with the same image.

Jackcess and its database templates are third-party dependencies; see the reader
README for the dependency versions, licensing references, and deployment limits.
